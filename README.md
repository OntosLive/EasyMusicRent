# ONTOS.RENT

**Инструментальный фонд исполнительской музыки.**

Репозиторий `EasyMusicRent` содержит статический сайт аренды музыкальных инструментов. Фонд организует временный доступ к инструменту, подходящему человеку, его практике и сроку. Публичная страница модели или сцены описывает возможный запрос; сама по себе она не подтверждает наличие экземпляра.

Ранняя модель «газеты аренды вещей» сохранена в истории Git и исходных материалах. Текущая архитектура описана ниже; архив выпусков не является её публичным каркасом.

## Две страницы одной сущности

| Адрес | Назначение и форма |
| --- | --- |
| `/<slug>/` — N.0 | Короткий запросный вход: заголовок, контакт, диапазон проката, условия и переход «Подробнее». |
| `/details/<slug>/` — N.1 | Предметное раскрытие с шапкой ONTOS.RENT, собственным редакционным заголовком и дочерними переходами перед блоком 01. |

На главной это `/` и `/details/`. Формула перехода: **N.0 → N.1 → вход дочерней сущности**. Отдельного публичного N.2 нет: старые адреса `/karta/` переводят на соответствующее раскрытие.

Обе страницы темы открыты для индексации и входят в sitemap; у каждой собственный абсолютный self-canonical на действующем домене. Решение владельца от 7 октября 2026 отменяет прежнее общее ограничение N.1. Самостоятельные намерения и содержание пары сохраняются: доступ к инструменту и предметное понимание. Восемь страниц условий остаются вне sitemap со своим нынешним режимом индексации; технические перенаправления сохраняют `noindex` и также исключены из sitemap.

Контакт, футер и CSS общие; полная шапка развёрнутой страницы не переносится автоматически в короткую. На N.1 за контактом и футером следует необязательная свёрнутая «Документация» с релевантными первичными материалами. Исследовательские каталоги и редакционные основания сохраняются в репозитории.

## Предметная сеть

Главное раскрытие открывает тринадцать семейств музыкальных инструментов. У каждой сущности есть основной предметный родитель. Обучение, исполнительская задача, срок, география, производитель и культурная сцена дают дополнительные входы и связи.

Один инструмент может быть достижим из разных разделов. Новый адрес требует самостоятельного содержания; перестановка слов и замена города сами по себе не создают новую тему. Перед наполнением нужно сопоставить предложение со всем существующим корпусом.

## Исходники и сборка

- `content/sections/*.json` — новые предметные тексты и связи.
- `content/legacy-metadata.json` — поисковые и редакционные заголовки, родители унаследованных страниц.
- Сохранённые HTML — источник ранее написанного содержания. Их локальная рамка не определяет опубликованную страницу.
- `content/aliases.json` — объединённые адреса.
- `scripts/site_core.py` — единый компилятор; `assets/canon.css` — общий стиль.

Выход сборки — HTML и CSS в `_site/`. Внутренняя документация и исходные данные в публичный выход не включаются. Обязательного JavaScript на стороне посетителя нет.

В рабочем окружении с Python 3.12 выполнять из корня репозитория:

| Шаг | Команда |
| --- | --- |
| Установить зависимости | `python -m pip install -r requirements-site.txt` |
| Проверить полный состав тем | `python scripts/content_inventory.py --output _audit/inventory.json` |
| Найти близкие темы перед добавлением | `python scripts/content_inventory.py --match "контрабас"` |
| Проверить весь граф, повторы и самоссылки | `python scripts/link_audit.py --report _audit/links.json` |
| Собрать сайт | `python scripts/site_core.py --output _site --report _audit/build.json` |
| Запустить тесты | `python -m unittest discover -s tests -v` |
| Проверить готовые страницы | `python scripts/validate_site.py --site _site --report _audit/build.json --output _audit/validation.json` |

Инвентаризация обнаруживает точные дубли и отсутствующих родителей. Смысловую самостоятельность и фактическую точность текста нужно проверять отдельно.

Отчёт связности сохраняет прежние верхние показатели для сравнения с историческими волнами. Блок `strict_lateral` отдельно исключает прямого объявленного родителя страницы и её прямых детей. Полные определения и списки страниц находятся в `_audit/links.json`; отчёт включён в артефакты автоматических проверок.

## Сохранение и публикация

Изменения передаются в GitHub через интеграцию проекта. После изменения `main` workflow [Build, validate and deploy ONTOS.RENT](.github/workflows/jekyll-gh-pages.yml) собирает и проверяет сайт, затем публикует артефакт в GitHub Pages. Отдельный [Canon audit](.github/workflows/canon-audit.yml) сохраняет проверку и исходный снимок.

Сохранённый коммит, успешная сборка и успешная публикация проверяются отдельно. Локальная сборка сама по себе сайт не публикует.
