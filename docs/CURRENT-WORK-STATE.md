# CURRENT WORK STATE — читать перед любой работой с репозиторием

Дата фиксации: 7 октября 2026 года, московское время.

Этот файл является **единственным указателем текущего рабочего состояния** проекта ONTOS.RENT.

## Единственный канал работы

- опубликованная и каноническая ветка: `main`;
- единственная постоянная рабочая ветка: `codex/active`;
- все остальные `codex/*` считать историческими / архивными именами и **никогда не продолжать по ним работу автоматически**.

Старое имя ветки, более поздняя дата коммита или знакомое название wave не являются основанием для продолжения.

## Обязательное восстановление после нового чата или обрыва ответа

Перед любым изменением репозитория:

1. Получить текущий SHA `main`.
2. Получить текущий SHA `codex/active`.
3. Сравнить `main...codex/active`.
4. Дальше действовать только по результату:
   - `identical`: проверить успешный выпуск для точного SHA `main`; только затем начинать следующий пакет от этого состояния;
   - `active ahead, behind = 0`: продолжить ровно незавершённый пакет из `codex/active`;
   - `active behind, ahead = 0`: синхронизировать `codex/active` с `main`, старую работу не восстанавливать;
   - `diverged`: **не писать новый контент**. Сначала разобрать расхождение и вернуть один линейный канал.
5. Никогда не выбирать рабочую ветку по памяти предыдущего чата.
6. Совпадение веток подтверждает сохранённое состояние, но не публикацию. Если выпуск для точного SHA `main` выполняется, отсутствует или завершился ошибкой, сначала закрыть выпуск текущего пакета. При ошибке разобрать журнал и исправить причину в `codex/active`; новые предметные волны не начинать. При ожидании сохранить точку и проверить тот же выпуск при следующем входе, без частых повторных опросов.

## Жизненный цикл пакета

1. `codex/active` синхронна с `main`.
2. Цельный пакет изменений делается только в `codex/active`.
3. Внутри пакета выполняются дешёвые локальные/структурные проверки.
4. После завершения пакета `main` переводится fast-forward на head `codex/active`.
5. Запускается один release workflow.
6. Пакет завершён только после успешного выпуска для точного SHA `main`. Ветки становятся одинаковыми раньше, на шаге 4; это ещё не разрешает следующий пакет.
7. Новая отдельная wave/fix/reconcile ветка для обычной работы **не создаётся**.

Если нужен эксперимент, он не становится рабочей линией и не может быть автоматически восстановлен в следующем чате.

- единственным чистым продолжением текущего `main` была `codex/conductivity-wave-11`: ahead 5, behind 0.

## Продолжение при долгой работе и обрыве связи

Точная техническая причина прежних обрывов по доступным материалам не установлена. Длинные цепочки сетевых операций, повторные ожидания GitHub Actions и начало следующей волны в том же ответе создают риск незавершённого шага. Рабочий протокол сохраняет одну точку продолжения независимо от причины обрыва.

Уточнение владельца от 7 октября: продолжать последовательными пакетами в рамках доступного времени работы; завершение одного пакета не является причиной автоматически заканчивать ответ.

Рабочий режим:

- длинные локальные проверки запускать с ранним возвратом управления и отдельным журналом; не блокировать диалог ожиданием одного процесса;
- во время активной работы сообщать содержательный результат или текущий этап не реже чем раз в 60 секунд; пустые сообщения не считаются способом предотвращения тайм-аута;
- независимые предметные участки разбирать параллельно, изменения собирать в один проверяемый пакет;
- сохранять законченный пакет в `codex/active`, обновляя этот указатель вместе с ним; после проверки продвигать `main` и подтверждать выпуск;
- пока выпуск выполняется, можно читать и готовить следующий участок; следующий пакет изменений начинается после успешного выпуска предыдущего;
- проверять ход длительного выпуска с разумным интервалом, без частого повторного опроса;
- после успешного выпуска продолжать ближайший предметно обоснованный участок, пока остаются разрешённая работа и доступные ресурсы;
- при реальном ограничении доступа, времени или среды оставить точную сохранённую точку и назвать ограничение; не объявлять проект законченным по числу страниц или рёбер;
- не повторять полный аудит веток без признака расхождения.

Эти меры сохраняют работу и обратную связь. Они не меняют платформенные ограничения длительности чата и не гарантируют отсутствие разрыва соединения.

При обрыве ответа точку продолжения определяют сохранённый head `codex/active` и состояние выпуска для `main`.
