## Архитектурный смысл

До этой волны человек чаще входил через:

**инструмент → модель → задача**  
или  
**преподаватель → рекомендация → предметная проверка**.

Теперь появляется третий симметричный маршрут:

**симптом / препятствие → проверяемое движение или слышимый результат → различение причины → предметная функция → временный инструмент → повторная проверка.**

Все 64 страницы имеют один поперечный родитель:

`instrument-po-trebovaniyam-k-kachestvu`.

Это не новое семейство фонда. Маршрут лишь переводит язык пользователя «тяжело», «туго», «не слышно», «не хватает» в уже существующую предметную сеть.

## Доказательная политика

См. [technical-obstacle-routes-wave-01-evidence.json](../research/technical-obstacle-routes-wave-01-evidence.json).

У страниц `sources: []`, потому что волна не вводит новых точных характеристик конкретных моделей. Техническая фактология остаётся на предметных страницах с первичными источниками.

## Лёгкая проверка до публикации

- четыре JSON-файла разбираются;
- 16 + 16 + 16 + 16 = 64;
- все 64 slug уникальны внутри волны;
- обязательные поля заполнены;
- у всех страниц один существующий поперечный родитель;
- у всех страниц `sources: []`;
- структура 13 предметных семейств не менялась.

Полный граф ссылок, исторические пересечения и весь опубликованный артефакт проверяет один release build.

## Что сознательно не делалось

- телесный симптом не превращался в медицинский диагноз;
- инструмент не объявлялся причиной проблемы до сравнительной проверки;
- «легче», «мягче», «меньше» и «быстрее» не трактовались как универсально лучше;
- недостающая функция публиковалась только как связь с реальной исполнимостью программы;
- не создавались городские, сроковые и синонимические дубли;
- наличие страницы не означает наличие конкретного экземпляра фонда.

## Следующий масштаб

После зелёной публикации корпус должен составить **1916 тем**.

Следующий естественный этап уже не обязан снова быть чисто экстенсивным. После нескольких крупных cross-route волн особенно полезны:

1. измерение проводимости сети;
2. поиск смысловых дублей и тупиковых страниц;
3. усиление внутренних переходов между cross-route и предметными страницами;
4. второй содержательный проход по наиболее трафикоёмким или наиболее перспективным узлам.
