## Архитектурный смысл

Раньше человек чаще входил через название инструмента, состав или преподавательскую рекомендацию.

Теперь появляется ещё один симметричный маршрут:

**ощущаемая проблема → проверяемое различение → возможные причины → предметная конфигурация → временная проба → решение**.

Это важный переход: пользователь может не знать, какой инструмент ему нужен, но уже знать, **что именно у него не получается**.

Все 64 страницы имеют поперечный родитель `instrument-po-trebovaniyam-k-kachestvu`. Структура 13 предметных семейств не меняется.

## Лёгкая проверка

- четыре JSON-файла разбираются;
- 16 + 16 + 16 + 16 = 64;
- 64 уникальных slug;
- обязательные поля заполнены;
- единый существующий поперечный родитель;
- внутренние дубли отсутствуют.

Полный граф и исторические пересечения проверяет release build.

## Следующий шаг после зелёной публикации

После 1916 тем дальнейший рост адресов уже стоит сравнивать с **проводимостью существующей сети**. Следующая работа может идти двумя путями:

1. ещё одна cross-route волна по жизненным ограничениям: срок, транспорт, временное жильё, ремонт, гастрольная замена;
2. начать измерять, насколько 1916 тем действительно приводят человека от первого входа к полезному следующему узлу без тупиков и повторов.

Вторая линия становится всё важнее по мере насыщения корпуса.
