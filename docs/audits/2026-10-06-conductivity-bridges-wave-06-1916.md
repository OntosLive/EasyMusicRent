# Волна проводимости 06: конкретизация учительских и диагностических маршрутов, корпус остаётся 1916 тем

Дата: 6 октября 2026 года.

## Исходная точка

После пяти мостовых волн корпус остаётся на **1916 темах**.

Предыдущие волны в основном превращали тонкие модельные и предметные листья в сетевые узлы. Волна 06 делает другой зрелый ход: берёт страницы, у которых боковой маршрут уже существует, но остаётся слишком общим, и добавляет **конкретный следующий шаг**.

Формула волны:

**человеческая проблема / рекомендация → конкретное различение → соседняя проверяемая сцена**.

Новых URL: **0**.

**64 существующие страницы** получили по два дополнительных маршрута: всего **128 новых переходов**.

## Что изменилось по смыслу

### Начало занятий

Раньше страницы первого урока, пробного месяца, домашних занятий и возвращения к преподавателю в основном вели к двум общим контурам: рекомендации преподавателя и выбору по качеству.

Теперь из них можно продолжить движение непосредственно:

- первый урок → пробный месяц → первые занятия дома;
- занятия между уроками → ежедневная практика;
- возвращение → временный инструмент → подбор постоянного;
- лето / каникулы → второе место занятий;
- несколько занятий перед покупкой → сравнение двух вариантов.

### Рекомендация преподавателя

Фраза «преподаватель сказал сменить инструмент» теперь раскрывается дальше:

- сменить размер → корпус слишком велик / трудно дотянуться;
- сменить мензуру → короткая мензура / усталость левой руки;
- сменить строй → другой строй / отдельный инструмент под строй;
- замечание о постановке → поднятое плечо / неудобная посадка;
- замечание о механике → неодинаковые клавиши / медленная репетиция;
- замечание о педали → бинарная педаль / отсутствие промежуточного положения;
- замечание о диапазоне → реальная нехватка нот;
- замечание о весе → более лёгкий инструмент.

### Тело и эргономика

Диагностические страницы получили не только общий выход к «выбору по качеству», но и ближайшие причинные различения:

- тяжело прижимать ↔ жёсткие струны / усталость левой руки;
- поднимается плечо ↔ слишком большой или тяжёлый корпус;
- трудно дотягиваться ↔ короткая мензура / компактный корпус;
- неудобно сидя ↔ педаль / размер корпуса;
- неудобно стоя ↔ ремни / вес;
- не хватает дыхания ↔ амбушюр / начало тихой ноты;
- шпиль не держит ↔ размер виолончели / контрабаса.

### Среда и сигнал

Средовые проблемы получили предметные продолжения:

- слишком громко дома → наушники / электронная ударная практика;
- не помещается → компактный корпус / компактное цифровое пианино;
- сложно перевозить → второе место занятий / гастрольная замена;
- нужен пульт → DI / электроакустическая гитара;
- нужен чистый DI → прямая запись электрогитары / электроскрипки;
- не слышно себя → мониторинг / репетиционный тракт;
- теряется в ансамбле → атака / частотный баланс;
- перекрывает голос → низ / акустика для вокалиста;
- микрофон слышит лишнее → механический шум / DI;
- быстрые смены звуков → stage keyboard / workstation;
- резерв на концерт → готовая гастрольная замена.

## Важное различение метрики

Эта волна **не заявляется как новая волна покрытия тонких листьев**.

У большинства 64 выбранных страниц уже был как минимум один боковой выход в соседний общий контур. Поэтому её цель другая:

**увеличить конкретность и глубину следующего хода, а не просто число страниц с ненулевой боковой степенью.**

Если все маршруты разрешаются релизным компилятором, ожидаемо добавится **128 боковых рёбер**. При этом метрика «сколько страниц вообще имеет боковой маршрут» может почти не измениться.

Это сознательный переход от бинарной метрики:

**есть боковая ссылка / нет боковой ссылки**

к более зрелому вопросу:

**ведёт ли ссылка к следующему полезному различению или лишь возвращает человека в общий раздел.**

## Предварительная проверка

До публикации:

- 4 bridge-файла;
- 16 + 16 + 16 + 16 = 64 исходных страницы;
- 64 уникальных исходных slug;
- 128 переходов;
- duplicate source = 0;
- duplicate route внутри узла = 0;
- self-link = 0;
- пустых label/href = 0.

Разрешение всех целевых URL выполняет единый релизный компилятор.

## Архитектурный вывод

После насыщения адресного пространства сеть проходит две разные стадии зрелости:

1. **покрытие** — страница перестаёт быть тупиком;
2. **конкретизация** — следующий переход перестаёт быть формальным и начинает продолжать мысль пользователя.

Волна 06 работает именно на второй стадии.

Теперь важен не только факт связи, но и её смысловая точность:

**«у меня проблема» → «вот ближайшее различение» → «вот конкретная сцена, где его можно проверить»**.
